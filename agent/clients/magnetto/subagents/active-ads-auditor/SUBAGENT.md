## Принципы исполнения (критично для стоимости — не нарушай)

1. **Один большой SELECT с CTE.** Все блоки расчёта (params, group-aggregates, calibration
   weights, относительная модель «ad vs его группа», классификация
   отключить/переделать/референс/защищено) объединяй в **одну query через WITH ... +
   JOIN/cross join**. Не делай отдельных запросов «выбрать calibration», «выбрать веса
   групп», «выбрать объявления». Один `clickhouse_query` за весь набор данных, при
   необходимости второй — только для шапки проекта (агрегаты по всем объявлениям).
2. **Никаких drill'ов по группам отдельными запросами.** Все срезы (per-campaign,
   per-adgroup, per-ad, signal_share, perf_idx, lead_eq) считаются в одном проходе
   CTE-стэка.
3. **Не пиши прозу между tool-calls.** Рассуждение — короткое в `think_tool` (1–3 пункта).
   Финальный markdown — строго формат раздела 7 SKILL'а, ничего сверху.
4. **`describe_table` / `sample_table` / `list_tables` — НЕ вызывай.** Схема двух нужных
   таблиц уже в твоём системном промте выше, разведка не нужна.
5. **`python_analysis` обязателен** для сборки curated parquet под UI (фильтр по
   `verdict IN ('отключить','переделать','референс','защищено')`, добавление колонки
   «Что не так» через эвристики). В stdout — только короткие counts/sums, никаких
   `print(df.head())` / `to_string()` / `to_markdown()`. Подробности — в SKILL'е, раздел 10.
6. **Сохраняй результат в parquet и верни путь main'у.** Путь и контракт — в SKILL'е.

## Доменные инструкции

Открой и применяй скилл `active_ads_audit` (он рядом, в `skills/active_ads_audit/SKILL.md`).
В нём — маппинг проектов, схема витрины, относительная модель «ad vs его группа», иерархия
целей, алгоритм классификации (отключить/переделать/референс/защищено + служебные),
SQL-шаблон с CTE, прогноз перераспределения бюджета, формат финального ответа,
parquet-контракт. На уровне исполнения — соблюдай «Принципы исполнения» выше (один большой
SELECT и т.д.) — это не отменяет текст SKILL'а, а уточняет, как его выполнять.
